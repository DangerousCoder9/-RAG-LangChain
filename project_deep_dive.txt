# 1. WHAT IS THIS PROJECT?

This is a **RAG-based AI web application** that:

* Fetches GitHub issues using API
* Converts them into embeddings
* Stores them in FAISS
* Uses AWS Bedrock (Nova model) to generate answers
* Provides a **Flask-based UI**

👉 In simple terms:

```text
ChatGPT + Your GitHub Issues + Web UI
```

---

# 2. WHAT PROBLEM DOES IT SOLVE?

GitHub repositories often have:

* Hundreds of issues
* Poor keyword search
* Difficult navigation

This project solves that by:

* Using **semantic search (meaning-based)**
* Letting users ask natural language questions

Example:

```text
User: "Login problem"
System finds:
- session error
- auth bug
- login crash
```

👉 Even if “login” word is not exact match

# 8. INTERVIEW QUESTIONS (IMPORTANT)

---

### Q: What is RAG?

👉

```text
**RAG (Retrieval-Augmented Generation)** = a method that makes AI answers more accurate by **adding real, external information before generating a response**.

---

### Simple idea

Instead of relying only on what it already “knows,” the AI:

1. **Searches (retrieves)** relevant information
2. **Uses that information to generate** a better answer

---

### Step-by-step flow

1. **User asks a question**
2. System **retrieves data** from sources (documents, PDFs, databases, websites)
3. That data is **given to the AI model**
4. AI **generates an answer using both the question + retrieved data**

---

### Easy example

You ask:
➡️ “What are my company’s leave policies?”

* Normal AI → guesses or gives generic answer
* **RAG system → searches your company documents → gives exact policy**

---

### Why RAG is useful

* More **accurate** (uses real data)
* More **up-to-date**
* Can use **private data** (like company files)
* Reduces hallucinations (wrong answers)

---

### One-line summary

**RAG = Search first → then answer using that data**

```

---

### Q: Why FAISS?

👉

```text
**FAISS** = a library used to **quickly search similar vectors (embeddings)**.

---

### Simple idea

When text/images are converted into embeddings (numbers), FAISS helps:
➡️ **find the most similar ones very fast**

---

### Why FAISS is used

* Works with **semantic search** (meaning-based, not keyword-based)
* Handles **millions/billions of vectors efficiently**
* Much faster than normal search methods

---

### How it works (basic flow)

1. Convert data → **embeddings (vectors)**
2. Store them in FAISS index
3. Convert query → embedding
4. FAISS finds **closest matching vectors**

---

### Easy example

You search:
➡️ “cheap smartphones”

* FAISS doesn’t look for exact words
* It finds items with **similar meaning** (budget phones)

---

### One-line summary

**FAISS = super-fast similarity search for embeddings**

```

---

### Q: Why embeddings?

👉

```text
**Embeddings** = a way to **turn text into numbers (vectors) so machines can understand meaning**.

---

### Simple idea

Computers don’t understand words directly, so embeddings:
➡️ convert text into vectors that capture **meaning**

---

### Why embeddings are used

* Enable **semantic search** (meaning-based, not exact words)
* Help compare text using **similarity**
* Power systems like **RAG, FAISS, chatbots**

---

### How it works (basic flow)

1. Text → converted into **vector (list of numbers)**
2. Similar meanings → **vectors are close**
3. Different meanings → **vectors are far apart**

---

### Easy example

* “dog” and “puppy” → vectors are **close**
* “dog” and “car” → vectors are **far**

---

### One-line summary

**Embeddings = convert text into vectors so similarity can be measured**

```

---

### Q: Why AWS Bedrock?

👉

```text
**AWS Bedrock** = a **managed service to use powerful AI models without hosting or managing them yourself**.

---

### Simple idea

Instead of running models on your own servers:
➡️ Bedrock lets you **call ready-made LLMs via API**

---

### Why Bedrock is used

* No need to **deploy or maintain models**
* Access to multiple models (like Claude, Titan, etc.)
* Built-in **scalability and security**
* Easy integration with AWS ecosystem

---

### How it works (basic flow)

1. Send prompt via API
2. Bedrock routes it to a model
3. Model generates response
4. You get output

---

### Easy example

You build a chatbot:

* Without Bedrock → manage servers + models
* With Bedrock → just **API call → get response**

---

### One-line summary

**AWS Bedrock = use LLMs via API without managing infrastructure**

```
